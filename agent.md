## What this project is

- **Engine:** Unity 6.6, editor version `6000.6.2f1` (`ProjectSettings/ProjectVersion.txt`). The project uses the High Definition Render Pipeline (HDRP 17.6, since #31 on 2026-11-10); on Linux the editor runs on Vulkan.
- **Repository:** `https://github.com/AdaM404-dev/NET.runner-92`, with the Unity project at the repository root on `main`.
- **Assets:** the Northline hospital (main map since #31) in `Assets/NETRunner92/`: environment, HDRP materials, K-7 patrol robot, LATCH-07 arms and tablet, atmosphere; its production material in `Northline/`. The NEXUS character was deleted on 2026-11-10 (AdaM404's decision on #46). The warehouse was deleted in #31.
- **Scenes:** `Assets/NETRunner92/Scenes/Hospital_Exploration.unity` is the only scene in Build Settings; `LATCH07_ViewmodelCheck.unity` is a check scene. The warehouse scenes (`Warehouse`, `MainTest`, `CharacterPreview`) were deleted in #31.
- **Code:** all in feature folders under `Assets/NETRunner/` since #31 PR B: `Core`, `Settings`, `Player`, `World`, `Enemy`, `Atmosphere`, `Diagnostics`, each with its own assembly and namespace `NetRunner.<Feature>`; the hospital code is unchanged from Northline otherwise, except `Enemy` and `Atmosphere`, which follow the coding standard since #41 and #42 (#43–#45 do the rest, one feature each). Tests: 121 EditMode, 36 PlayMode, one of which runs the hospital's 95 checks (`docs/architecture/overview.md`). `NexusPlayer`, `NexusDoor` and the `MainMenu` prototype were deleted in #31.
- **Agent rules:** `AGENTS.md` is the one rule file for every agent (Claude Code loads it through `CLAUDE.md`, Codex reads it directly): sync with `main` before every change, workflow, ownership, code structure and the coding standard. **Human docs:** `README.md` explains opening/importing the project. `docs/README.md` is the entry to the knowledge base: a beginner learning path (`docs/guide/`), `docs/architecture/project-map.md` (where every file and object is), one note per system in `docs/systems/`, and `docs/architecture/before-new-scripts.md` (what must change before new gameplay scripts). `AGENTS.md` holds the shared rules and build/test commands; `CLAUDE.md` only Claude Code's additions.

## How agents should work here

1. Read the user's current request, this file, `README.md`, the relevant code, and the GitHub issue of any planned change (open issues labelled `decision`; the pinned Roadmap issue #5 lists them in order). Check `git status` before editing so another person's work is not overwritten.
2. Add a concise **Active work** row with your objective and the area you will touch. Keep that row current if the work takes multiple turns.
3. Preserve Unity `.meta` files and GUID relationships. Keep generated `Library`, `Temp`, `Logs`, and build output out of Git. Check scene, prefab, and package references when moving assets.
4. Make the requested change and run only meaningful validation for that change. State clearly when Unity editor or runtime behavior was not tested.
5. Before finishing, update **Current status** and **Open items** as needed, append a **Work log** entry, and close your **Active work** row. Include the result, changed files, verification, and commit or PR link if one exists. Do not erase earlier log entries.
